## Ревью и исправления
| # | Замечание | Сделано |
| --- | --- | --- |
| 1 | `enable_output_network_interface` в podkop 0.7.24 не заворачивает трафик роутера в туннель (он лишь привязывает direct-outbound к интерфейсу); трафик роутера идёт в туннель, если домен попал в списки (fake-IP, `mangle_output`) | **Проверено по коду podkop.** Секция-исключение `peers_ss_direct` (api.stealthsurf.net, api.github.com, github.com, *.githubusercontent.com) создаётся всегда, одним коммитом с первой ссылкой. Проверено: sing-box направляет их в `direct-out` |
| 2 | `[ -r /dev/tty ]` не доказывает терминал | `( exec </dev/tty )` |
| 3 | обрыв `wget | sh` | весь скрипт в `main()` |
| 4 | предупреждение о ведомых привязках — после сохранения | список привязок и подтверждение **до** сохранения (CLI и LuCI `token_check`) |
| 5 | в выборе секции — не-URL секции | только `proxy` + `url` |
| 7 | нет проверки целостности архива | `SHA256SUMS` в Release, `sha256sum` в установщике |
| 8 | частичное копирование / место после opkg | повторная проверка места, ошибка копирования прерывает с сообщением, старый код удаляется целиком |
| 10 | мастер: HTTP 0, classic-токен, прерывание на неверном токене, «осиротевший» контур | понятные сообщения, предупреждение о classic, повторный ввод, файл ротации пишется до `contour.json`, 403 → «нет права записи» |
| 11 | `assign_config` молча проглатывал ошибки | ошибки выводятся |
| 6 | без токена секция podkop не создаётся до первой ссылки | так и оставлено: секция без ссылки ломает старт podkop (`Proxy string is not set`) |
| 9 | после sysupgrade сохраняются только настройки | проверяется на этапе 10 |

## Решения / ограничения
- Ввод токенов и пароля виден на экране (ТЗ §4); код приглашения передаётся мастеру через переменную окружения, не argv.
- Токен «другого аккаунта» проверен только логически (второго аккаунта StealthSurf нет): список ведомых привязок строится по `contour.json`.
- `ghp_` (classic) принимается с предупреждением.
