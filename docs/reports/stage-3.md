# Этап 3 — хранилище и шифрование

Код: `store.uc` (GitHub Contents API), `crypto.uc` (uencrypt AES-256-CBC + HMAC-SHA256), тесты `tools/tests/{race.sh,store_race.uc,store_dump.uc}`.

## Формат
- Файл в репозитории: `{"schema":1,"enc":"PSE1.<base64(iv|ct|mac)>"}` — открыты только имя файла и номер схемы.
- MAC = HMAC-SHA256(mac_key, `"PSE1\0" + repo/path#schema + "\0" + iv|ct`) — шифр нельзя перенести в другой файл или подменить схему.
- Ключ контура = 100 000 итераций SHA-256 (пароль, соль); соль = SHA-256 от случайного `contour_id`. На роутере ~2 с, считается один раз.
- Подключи `enc`/`mac` разделены; MAC проверяется до расшифровки (нет padding oracle); сравнение за постоянное время.
- Анти-откат: максимальный `rev` каждого файла запоминается в ОЗУ; файл с меньшим `rev` отвергается.

## Проверки (роутер 1)
| Проверка | Результат |
| --- | --- |
| Две одновременные записи из двух shell (2×5, затем 2×4 после правок) | ✅ все 10 / 8 записей на месте, конфликты 7 / 4 — каждый повторён |
| Чтение с ETag | ✅ повторное чтение — 304 (после исправления экранирования кавычек в заголовке) |
| Сроки по `Date` GitHub | ✅ расхождение с часами роутера 0 с (после исправления месяца) |
| В репозитории только шифр | ✅ `test-stage3/*.json` = `{"schema":1,"enc":"PSE1…"}` |
| Подмена: шифр скопирован в другой файл | ✅ не расшифровывается |
| Неверный ключ / испорченный шифр | ✅ `decrypt` → null |

## Ревью и исправления
| # | Замечание | Сделано |
| --- | --- | --- |
| 1 | MAC не привязан к пути/схеме, возможен откат | AAD = repo/path#schema; анти-откат по `rev` |
| 2 | PUT с неизвестным исходом мог примениться дважды | при 0/5xx перечитываем и сравниваем git blob sha |
| 3 | повторы без джиттера | случайная пауза 0–1,2 с |
| 4 | любой 422 считался конфликтом | конфликт только при упоминании `sha` |
| 5 | ключ uencrypt в cmdline | принятый риск (у uencrypt нет другого способа), записан |
| 6 | схема: NaN, чтение при новой схеме | конверт без целой `schema` отвергается; новая схема читается, но не пишется |
| 7 | часы GitHub известны только после запроса | решения о замке принимаются только после чтения файла замка |
| 8 | >1 МБ, `list_dir` без ETag | проверка `encoding`; кэш ETag для каталогов |

## Решения
- Соль из `contour_id` (отдельного файла с солью нет), `contour_id` — случайный, без имени клиента.
- `ucode-mod-digest` (65 КБ) — зависимость для SHA-256.
