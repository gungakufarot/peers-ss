# Этап 4 — podkop: вставка, применение, диагностика, пинг

Код: `files/usr/share/peers-ss/podkop.uc`, CLI `peers-ss podkop status|setup|apply|diag`.

## Как сделано (по коду podkop 0.7.24)
- Управляемая секция `peers_ss` (`connection_type proxy`, `proxy_config_type url`, `mixed_proxy_enabled 1`, порт 2080 — первый свободный).
  Создаётся **одним коммитом вместе с первой ссылкой** (`apply --setup`). Списков доменов у секции нет → на трафик LAN она не влияет,
  пока администратор не задаст списки в LuCI podkop. KCA и `settings` не трогаются.
- Применение = `uci commit` (собственный каталог правок `/tmp/peers-ss/uci`, чужие несохранённые правки LuCI не коммитятся) +
  `/etc/init.d/podkop restart` — то же, что делает procd-триггер после «Сохранить и применить». Двойного рестарта нет (1× Stopping/Starting).
- Ожидание: каждые 5 с sing-box + запрос `generate_204` через mixed-прокси, не дольше 60 с (по реальному времени).
- Диагностика = роутерные проверки вкладки «Диагностика» LuCI: `check_dns_available`, `check_sing_box`, `check_nft_rules`, `check_fakeip`,
  `clash_api get_proxy_latency <секция>-out 5000`. `rules_other_mark_exist=1` — предупреждение (как в LuCI), нулевые счётчики nft — норма.
- Пинг через vless: Clash API (URL-test sing-box), прогрев + медиана 3; запасной путь — 3 запроса через mixed-прокси, медиана.
- Копии: `/etc/peers-ss/podkop.orig` (первое изменение), `/tmp/peers-ss/podkop.prev` (перед каждым).
- Защита LAN: если после применения sing-box не поднялся — возврат прежней ссылки; если и так не поднялся — `podkop stop` (возвращает dnsmasq).
- Блокировка `podkop.lock` против одновременных применений (CLI / служба / LuCI).
