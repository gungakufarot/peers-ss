## Найдено тестами и исправлено
1. **PATCH в той же локации оставил прежний сервер** (2511 → 2511, сменилась только ссылка). Теперь: исключаем серверы с IP текущего;
   после PATCH сравниваем `server_id` и IP; если не сдвинулся — один повтор с явным `server_id`, затем следующая локация.
2. После рестарта podkop DNS роутера поднимается не сразу → запись в GitHub (снятие замка) падала. Ждём DNS (`wait_dns`), повторы снятия замка.
3. При сбое чтения `contour.json` служба теряла привязку → работа по последней кэшированной копии.
4. DNS через sing-box на r2 нестабилен (`curl exit 6`) → при ошибке разрешения имени запросы повторяются через прямой резолв
   (1.1.1.1, 8.8.8.8, 9.9.9.9, 77.88.8.8) и `curl --resolve`.
5. Ротация по отчёту ведомого отменялась перепроверкой слоёв 3–4 у ротатора (у него-то всё работает) — см. «Решения».
6. Убитый посреди ротации процесс оставлял локальную блокировку → блокировки с PID владельца.

## Решения агента (отклонения/уточнения ТЗ)
- **`routers/<id>.json` — пульс раз в 30 мин** (ТЗ: раз в 6 ч), иначе нельзя обнаружить «не на связи > 1 ч» (ТЗ §9). Плюс запись при смене состояния.
- **Ротация по отчёту ведомого пропускает шаг 3** (перепроверка слоёв 3–4 у ротатора): блокировка у ведомого, у ротатора всё проходит,
  иначе тест (г) невыполним. Защита от ложных сигналов — правило «плохого канала».
- Применение ссылки другими роутерами — по `rev` новее применённого (ТЗ §5) + ссылка отличается.
- Пинг для ротации по отчёту — замеры ведомого (снимок локаций `loc_snapshot` в файле ротации, раз в 6 ч от роутера с токеном).
- Бот видит статусы роутеров через `cards/_contour.json` (пишет первый роутер на связи).
- Карточки и снимок локаций — роутер с токеном, первый по `router_id` среди живых.

## Известные ограничения
- r2: podkop настроен владельцем на DNS 1.1.1.1/UDP, у провайдера r2 этот путь нестабилен → диагностика podkop там красная
  (`dns_on_router: 0`), доставка ссылки может задерживаться. Настройки podkop вне управляемой секции не меняем.
- «Плохой канал» реализован, но отдельным тестом не проверялся (в списке проверок этапа его нет).
- Без GitHub остальные роутеры получают новую ссылку только через сверку роутера с токеном (раз в 10 мин) → 505 с в тесте;
  ведомые без токена ждут GitHub (так в ТЗ).
- Двойная смена сервера в режиме без GitHub возможна (ТЗ §5), риск снижает пауза 0–90 с.
